6. A real non-determinism in the reference's output writer
-----------------------------------------------------------
`dev/idealize_backbone.rewrite` re-parses the PDB it was handed and calls
`aa_model.get_ligands`, which returns a **Python `set`**. `','.join(ligands)`
then iterates that set, and CPython randomises string hashes, so the ligand
order handed to `make_indep` — and therefore the order of the HETATM block in
the final file — depends on `PYTHONHASHSEED`.

Measured, two runs of the *unmodified* reference, same seed, same config,
differing only in PYTHONHASHSEED:

    PYTHONHASHSEED unset (=0 here)   HETATM block: 6 OXM, then 44 NAD
    PYTHONHASHSEED=1                 HETATM block: 44 NAD, then 6 OXM
    the 111 ATOM lines                identical between the two runs

So `inference.deterministic=True` does not make the output file deterministic.
The port emits the ligands in input order (NAD, OXM), which matches
PYTHONHASHSEED=1; the diff in §5 is against that run. Reproducing the *other*
order would mean reproducing CPython's hash randomisation, which is not a
property of RFdiffusion2.

8. Rung 8 progress — 2026-08-10 (later)
----------------------------------------

Self-conditioning (`inference.str_self_cond=True`), T=2
  The flag is a real behavioural change, checked before it was tested: the
  reference's step-1 px0 moves by up to 0.974 A with it on, while step 0 is
  untouched (the guard is `t < T`, and the first step has t == T).

      t = 2   px0 7666 / 7881   max|d| 8.106e-6 A   (/rms 2.77e-6)
      t = 1   px0 7585 / 7881   max|d| 3.004e-5 A   (/rms 9.99e-6)
      generator after the loop  64 / 64 bit-identical

  Same residual as the non-self-conditioned run, i.e. self-conditioning adds
  no error of its own.  tests/parity_selfcond.rs

`diffuser.partial_T` — implemented, not exercisable on this input
  `validate_partial_diffusion` requires the contig to be an identity mapping
  over the whole input PDB. The demo contig is not, and **the reference itself
  crashes** (`IndexError: index 54 is out of bounds for dimension 0 with size
  54`) rather than reporting it. The port implements the same four checks and
  refuses with a message naming which one failed. Exercising the feature needs
  a whole-chain identity contig plus `inpaint_str` — a rung-8 config of its own.

Variable-length contig + `contigmap.length`  ***BYTE-IDENTICAL***
  `contigs=['5-15,A106-106,5-15']  contigmap.length=25-25`, T=2, L=75.

  `get_sampled_mask` resolves each range with CPython's `random.randint` and
  re-samples the whole contig until the total matches, so the number of draws
  is not a function of the contig alone. From `random.seed(0)` the reference
  sampled `10-10,A106-106,14-14` (10 + 1 + 14 = 25) and left CPython's
  generator at position 55, having twisted. The port reproduces the sampled
  mask exactly (tests/parity_varcontig.rs).

  End to end, port vs reference:

      287 lines, 181 atoms
      differing lines                    0 / 287        BYTE-IDENTICAL
      protein coordinates  max|d| 0.0000 A   (0 of 131 above 0.0005)
      ligand  coordinates  max|d| 0.0000 A   (0 of  50 above 0.0005)

  This is the first fully byte-identical end-to-end output, and it is the
  Stage 0 conclusion showing up in practice: the port is correctly rounded, so
  when the trunk's rare 1-ULP tie does not fire on a given trajectory, the
  whole file matches exactly. The demo contig's 9 differing lines are that tie
  firing once, not a systematic gap.

  Reference: 34.5 s.  Port: 93.3 s (L = 75, T = 2, 4 cores).
